bash ≥ 4.3 · socat

Saf bash ile bir web framework'ü.

Router, controller, view, model ve JSON API. Hepsi tek bir bash süreci içinde, istek başına neredeyse hiç fork açmadan çalışır.

Başla Örnek uygulama 
# routes/web.sh
route GET  '/'           'Home'  'index'
route GET  '/users/{id}' 'Users' 'show'

# app/controllers/Users.sh
function show()
{
	local -A user
	find User "${ROUTE_PARAMETERS[id]}" user \
		|| send_error 404
	render 'user' "name=${user[name]}"
}

Neler var?

Bir web framework'ünden beklenen parçalar, kısa ve tanıdık fonksiyon adlarıyla.

Router ve rota grupları

{id} parametreleri, 404/405 ayrımı. config/routes.sh ile /api, /api/v2 gibi prefix grupları.

Controller

Her action sıradan bir bash fonksiyonu. Controller istek sürecinde source edilir, fork açılmaz.

View

resources/views altındaki HTML şablonları, render ile doldurulan yer tutucularla.

Dört veri kaynağı

SQLite, MySQL ve PostgreSQL. Hangisinin kullanılacağını DB_CONNECTION belirler. Redis'e doğrudan /dev/tcp üzerinden bağlanılır.

Modeller

find, where, order_by, get, create, save, delete. Değerler her zaman kaçışlanır.

JSON API

json_record, json_collection, json_error ile yanıtı kurar, json ile gönderirsiniz.

Üç adımda başlangıç

macOS'ta /bin/bash 3.2 olduğu için sunucu PATH'teki yeni bash ile başlatılır.

1 Ayarla

cp .env.example .env
# DB_CONNECTION=sqlite
# DB_CONNECTION=pgsql

2 Migrasyon

bash scripts/migrate.sh

3 Çalıştır

bash server.sh
# http://localhost:3000
